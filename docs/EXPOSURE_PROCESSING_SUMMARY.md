# Exposure Processing Summary

This note describes how exposure is represented and transformed in `PixelTable`, including FITS load/save behavior and runtime model evaluation.

## Overview

Exposure enters the system from one of two paths:

1. Load from FITS (`SKYMAP.EXPOSURE` and optional `BANDS.EXPOSURE`).
2. Attach programmatically with `PixelTable.attach_exposure(...)`.

In both cases, per-pixel exposure is ultimately used by `Band.exposure_map(...)` and then multiplied into source model counts in `Band.pixel_counts(...)` and `Band._model_counts(...)`.

## Core Data Fields

Per band (`PixelTable.Band`):

- `pixel_exposure`: per-pixel exposure used at runtime by `exposure_map`.
- `count_exposure`: raw per-pixel exposure values as loaded from FITS exposure column before runtime normalization.
- `exposure`: scalar mean exposure for the band.
- `_exposure_dense`, `_exposure_lookup`: caches used by `exposure_map`.

Per table (`PixelTable`):

- `pixel_exposure`: concatenated per-pixel exposure across all bands.
- `meta_df['exposure']`: per-band mean exposure values.
- `pixel_exposure_df`: optional long-form table generated by `attach_exposure`.

## Runtime Usage in Model Counts

When a source model is attached, source counts are computed dynamically as:

- response weights from `Band.response(source, pix)`
- multiplied by source spectral value `source.model(band.energy)`
- multiplied by per-pixel exposure from `Band.exposure_map(pix)`

and then added to diffuse counts.

So exposure scaling directly controls the normalization of predicted source counts.

## Normalization Contract

`Band._exposure_normalization()` defines a band-dependent scale factor:

- `norm = 1 / (1e-14 * (sqrt(e0 * e1) * 1e-3) ** (-2.1))`

During FITS load in `_setup_from_arrays(...)`:

- `band.pixel_exposure = raw_exposure * norm`
- `band.count_exposure = raw_exposure`

This means runtime `pixel_exposure` is the normalized quantity expected by model-count calculations.

## FITS Load Path

`PixelTable._load_from_fits(...)`:

1. Reads `SKYMAP.EXPOSURE` into table-level `self.pixel_exposure` (raw order-sorted values).
2. Calls `_setup_from_arrays(...)`, which applies band normalization and sets both band-level `pixel_exposure` and `count_exposure`.
3. Rebuilds table-level `self.pixel_exposure` from normalized band arrays.
4. Populates per-band mean exposure from `BANDS.EXPOSURE` if present, otherwise from band means.

## FITS Save Path

`PixelTable.to_fits(...)` now writes `SKYMAP.EXPOSURE` in de-normalized form:

- For each band: `raw_exposure = band.pixel_exposure / band._exposure_normalization()`
- Concatenates all bands and stores that array in the FITS `EXPOSURE` column.

This preserves a correct round-trip because load-time normalization in `_setup_from_arrays(...)` restores the runtime values.

## Programmatic Exposure Attachment

`PixelTable.attach_exposure(exposure_by_band, ...)` accepts per-band exposure specs as:

- scalar
- per-band sparse vector of length `len(band.pix)`
- full-sky map vector of length `12 * nside^2`
- callable (including map-like objects exposing `.values` or `.map_values`)

For each band it sets:

- `band.pixel_exposure`
- `band.count_exposure`
- `band.exposure`
- clears exposure caches (`_exposure_dense`, `_exposure_lookup`)

Then updates table-level exposure fields (`pixel_exposure`, `meta_df['exposure']`, `pixel_exposure_df`).

## Practical Check for Correct Scaling

If likelihood scans appear nearly flat under large norm changes, first verify:

1. `band.pixel_exposure` is non-zero and in the expected runtime scale.
2. Dynamic source counts (`response * flux * exposure`) are of similar order to FITS source counts for representative bands.
3. Round-trip behavior (`to_fits` -> `from_fits`) preserves `pixel_exposure` as expected.

A severe mismatch here can make source contributions numerically negligible and hide the expected likelihood maximum.
